# glitch: agent notes

**This checkout is live.** install.sh symlinks it into place, so the next Super+D runs whatever is on disk. glitch's own agent runs in `WORKDIR` (~/Work) and can edit this repo mid-turn.

- **Replace bin/glitch atomically** (temp file, then `mv`): bash reads scripts lazily, and a running `_turn`/`_live` keeps reading the old inode.
- **Test turns in a scratch runtime:** `XDG_RUNTIME_DIR=$(mktemp -d) setsid glitch _turn "…" true` (`GLITCH_AGENT=codex` to pick the agent). The live runtime holds the user's session id, history and turn queue, so a test there resumes or cancels their real conversation. A stand-in `claude`/`codex` early in PATH exercises the error and needs-you paths.
- **plugin/ is a keepLoaded panel:** QML edits need `omarchy restart shell`. Never restart the shell while the screen is locked: the lock screen is the shell's. After editing glitch.frag, recompile with `qsb --qt6 -o plugin/glitch.frag.qsb plugin/glitch.frag` and commit the .qsb (it's the fallback when qt6-shadertools is missing). qsb is `/usr/lib/qt6/bin/qsb`, or without root: unpack the `qt6-shadertools` package under `~/.local/share/glitch/qsb` and run it with `LD_LIBRARY_PATH=…/qsb/usr/lib` (install.sh looks there too).
- **The orb has two inputs:** the state and reaction over IPC (what it feels), and live signals appended to `$XDG_RUNTIME_DIR/glitch/orb.events` with `ev` (what is happening: `tok`, `tool`/`end`, `ctx`, `say`, `hush`, `turn`; listed at the top of Glitch.qml). Anything fast or factual is a signal, never a decision-model question. `omarchy-shell -q glitch event "tool x run"` injects one by hand.
- **Seeing the orb without the desktop:** screenshots hang when the display is asleep and show only the lock screen when locked. The shader needs a GL surface, which Qt's `qml` runtime gets through Xwayland (`QT_QPA_PLATFORM=xcb DISPLAY=:0`) even then; a copy of Glitch.qml with the Quickshell parts stubbed runs there and `grabToImage` saves frames.
- **Omarchy notifications:** only `-u critical` stays on screen, and `-r <id>` updates a card in place. The shell ignores D-Bus CloseNotification; `omarchy-shell notifications dismiss <text>` closes every card whose summary *contains* the text, from any app. The body is StyledText (escape `& < >`) and must stay valid UTF-8 (cut by characters).
- **Hyprland config is Lua:** `o.bind(keys, desc, "cmd")` (/usr/share/omarchy/default/hypr/helpers.lua), `hyprctl dispatch 'hl.dsp.…'`, and `hyprctl configerrors` after `hyprctl reload`.
- **Adapters share the line protocol** documented above `adapter_claude`. Each must end with `exit <status>`: a turn with no result line is a failure. Every `tool` line carries an id and gets a `toolend`: the comet, the radar and the moons run from one to the other.
- **Keep the vocabularies in sync:** the MOOD list in voice-prompt.md matches the `.mood` keys in reactions.json. Palette, pattern and motion names match Glitch.qml (`palettes`, `patterns`) and the pattern indices in glitch.frag. decide's mood options are the orb's (they drive the excited and surprised flourishes), not the agent's.
- **Looks are designed whole, never blended.** The decision model picks one option per question and the orb eases between looks. A new look is a palette, pattern, motion and voice chosen together (MOOD `clear`: mint, fine grain, breathe, two chirps), goes in reactions.json, and stays out of decide's lists so it can't be mixed into other moods.
- **The orb's taste:** flat and minimal on a globe edge (no lighting, no hard border), the eye is the pattern (centred and magnified at the gaze point), and distortion stays around 1% of rim and 2 to 4% of stretch. More than that reads as cartoony. Sounds come only from the cue synth's six voices.
- **Rings mean listening:** nothing shown while working (decide's choices or the `tool.*` reactions) uses rings.
- **Remote control** (`systemd/glitch-remote*`, `glitch _reap`): free sessions by restarting the whole server, never by killing one session's process. The app keeps showing a killed session connected while its turns hang.
- **Never** `bypassPermissions` or Codex's `--dangerously-bypass-*` for glitch's turns, even for an agent `omarchy-agent` runs that way (grok): otherwise glitch runs agents with omarchy-agent's modes (glitch-remote's `bypassPermissions` is the user's choice; leave it). Tap-toggle, not hold, because releases of modifier-chord keys get lost.

Debug: `tail -f $XDG_RUNTIME_DIR/glitch/glitch.log`, `omarchy-shell -q glitch set '{"state":"thinking","reaction":{…}}'`, `libexec/preview`, `journalctl --user -u glitch-mind -u glitch-remote`, `quickshell log -p $OMARCHY_PATH/shell`.
