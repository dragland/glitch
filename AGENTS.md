# glitch: agent notes

**This checkout is live.** install.sh symlinks it into place, so the next Super+D runs whatever is on disk. glitch's own agent runs in `WORKDIR` (~/Work) and can edit this repo mid-turn.

- **Replace bin/glitch atomically** (temp file, then `mv`): bash reads scripts lazily, and a running `_turn`/`_live` keeps reading the old inode.
- **Test turns in a scratch runtime:** `XDG_RUNTIME_DIR=$(mktemp -d) setsid glitch _turn "…" true` (a stand-in that reports a context window still rewrites the real `~/.local/share/glitch/ctx.window`) (`GLITCH_AGENT=codex` to pick the agent). The live runtime holds the user's session id, history and turn queue, so a test there resumes or cancels their real conversation. A stand-in `claude`/`codex` early in PATH exercises the error and needs-you paths.
- **plugin/ is a keepLoaded panel:** QML edits need `omarchy restart shell`, which refuses while the screen is locked (the lock screen is the shell's): don't kill quickshell to get around it. After editing glitch.frag, recompile with `qsb --qt6 -o plugin/glitch.frag.qsb plugin/glitch.frag` and commit the .qsb (it's the fallback when qt6-shadertools is missing). qsb is `/usr/lib/qt6/bin/qsb`, or without root: unpack the `qt6-shadertools` package under `~/.local/share/glitch/qsb` and run it with `LD_LIBRARY_PATH=…/qsb/usr/lib` (install.sh looks there too).
- **The orb has two inputs:** the state and reaction over IPC (what it feels), and live signals appended to `$XDG_RUNTIME_DIR/glitch/orb.events` with `ev` (what is happening; listed at the top of Glitch.qml). Anything fast or factual is a signal, never a decision-model question. Only the script knows when work starts and ends (`turn`, `rest`): the plugin never infers it from the state, which also changes for an approval or a recording mid-turn. `omarchy-shell glitch event "tool x run"` injects one (prints `ok`; set a `tool` state first or nothing shows).
- **Seeing the orb while the screen is locked or asleep** (screenshots hang or show the lock): stub the Quickshell imports in a copy of Glitch.qml, run it with `QT_QPA_PLATFORM=xcb DISPLAY=:0 /usr/lib/qt6/bin/qml` (`GLITCH_RT` points it at a scratch orb.events) and save frames with `grabToImage`.
- **Omarchy notifications:** only `-u critical` stays on screen, and `-r <id>` updates a card in place. The shell ignores D-Bus CloseNotification; `omarchy-shell notifications dismiss <text>` closes every card whose summary *contains* the text, from any app. The body is StyledText (escape `& < >`) and must stay valid UTF-8 (cut by characters).
- **Hyprland config is Lua:** `o.bind(keys, desc, "cmd")` (/usr/share/omarchy/default/hypr/helpers.lua), `hyprctl dispatch 'hl.dsp.…'`, and `hyprctl configerrors` after `hyprctl reload`.
- **Adapters share the line protocol** documented above `adapter_claude`. Each must end with `exit <status>`: a turn with no result line is a failure. Every `tool` line carries an id and gets a `toolend`: the comet, the radar and the moons run from one to the other.
- **Keep the vocabularies in sync:** the MOOD list in voice-prompt.md matches the `.mood` keys in reactions.json. Palette, pattern and motion names match Glitch.qml (`palettes`, `patterns`) and the pattern indices in glitch.frag. decide's mood options are the orb's (they drive the excited and surprised flourishes), not the agent's.
- **MOOD `clear` is one designed look** (mint, fine grain, breathe, chirp) in reactions.json. decide asks nothing for it and never carries its palette into the next turn, and `mint`/`fine` stay out of decide's lists so they can't be mixed into other moods. Add a new whole look the same way. Never blend decide's probabilities into in-between looks.
- **The orb's taste:** flat and minimal on a globe edge (no lighting, no hard border), the eye is the pattern, and distortion stays around 1% of rim and 2 to 4% of stretch. More than that reads as cartoony. Sounds come only from the cue synth's six voices.
- **The rings pattern stays out of work:** decide's working choices and the `tool.*` reactions never use it, so a live mic looks distinct. Travelling rings are voice (in for the user, out for glitch); a returning moon's ping is the only ring during work.
- **Remote control** (`systemd/glitch-remote*`, `glitch _reap`): free sessions by restarting the whole server, never by killing one session's process. The app keeps showing a killed session connected while its turns hang.
- **Never** `bypassPermissions` or Codex's `--dangerously-bypass-*` for glitch's turns, even for an agent `omarchy-agent` runs that way (grok): otherwise glitch runs agents with omarchy-agent's modes (glitch-remote's `bypassPermissions` is the user's choice; leave it). Tap-toggle, not hold, because releases of modifier-chord keys get lost.

Debug: `tail -f $XDG_RUNTIME_DIR/glitch/glitch.log`, `omarchy-shell -q glitch set '{"state":"thinking","reaction":{…}}'`, `libexec/preview`, `journalctl --user -u glitch-mind -u glitch-remote`, `quickshell log -p $OMARCHY_PATH/shell`.
