# glitch: agent notes

**This checkout is live.** install.sh symlinks it into place, so the next Super+D runs whatever is on disk. glitch's own agent runs in `WORKDIR` (~/Work) and can edit this repo mid-turn.

- **Replace bin/glitch atomically** (temp file, then `mv`): bash reads scripts lazily, and a running `_turn`/`_live` keeps reading the old inode.
- **Test turns in a scratch runtime:** `XDG_RUNTIME_DIR=$(mktemp -d) setsid glitch _turn "…" true` (`GLITCH_AGENT=codex` to pick the agent). The live runtime holds the user's session id, history and turn queue, so a test there resumes or cancels their real conversation. This also applies to a worktree's `bin/glitch`: without scratch `XDG_*` it uses the live runtime dir. A stand-in `claude`/`codex` early in PATH exercises the error and needs-you paths; one that reports a context window still overwrites the real `~/.local/share/glitch/ctx.window`, which the scratch runtime does not cover.
- **Test the portal only with scratch `XDG_RUNTIME_DIR`, `XDG_DATA_HOME` and `XDG_CONFIG_HOME`:** `GLITCH_PORTAL_PLAIN=1 bin/glitch portal` then serves plain HTTP on 127.0.0.1. A test pairing in the real data dir lands in the real devices file and works on the live portal. Scratch data has no voice, so `glitch pair` refuses: open a pairing by writing `$XDG_RUNTIME_DIR/glitch/phone/pair` as `{"hash": "<sha256 of 6 digits>", "expires": <epoch s>, "tries": 0}`, or write `devices` directly.
- **plugin/ is a keepLoaded panel:** QML edits need `omarchy restart shell`. It refuses while the screen is locked, because the lock screen is the shell's: don't kill quickshell to get around it.
- **One orb, two hosts:** its logic and look live in `plugin/orb.mjs` and `plugin/orb.glsl`. `Glitch.qml` (desk) and `web/orb.js` (phone) only feed inputs and draw; never put orb behaviour in a host. The shader hash is integer-based on purpose: sin-based hashes differ per GPU, so desk and phone would disagree.
- **After editing orb.glsl,** run `plugin/build-shader` and commit `plugin/glitch.frag.qsb` (the fallback when qt6-shadertools is missing). Without root, unpack the `qt6-shadertools` package under `~/.local/share/glitch/qsb`; build-shader looks there too.
- **The orb has two inputs:** the state and reaction over IPC, and live signals that `ev` appends to `$XDG_RUNTIME_DIR/glitch/orb.events` (listed at the top of orb.mjs). Anything fast or factual is a signal, never a decision-model question. Only the script knows when work starts and ends (`turn`, `rest`). The plugin must not infer it from the state, which also changes for an approval or a recording mid-turn.
- **Seeing the orb while the screen is locked or asleep:** screenshots hang or show the lock. Stub the Quickshell imports in a copy of Glitch.qml next to orb.mjs, run it with `QT_QPA_PLATFORM=xcb DISPLAY=:0 /usr/lib/qt6/bin/qml`, and save frames with `grabToImage`. `GLITCH_RT` points it at a scratch orb.events.
- **Omarchy notifications:** only `-u critical` stays on screen, and `-r <id>` updates a card in place. The shell ignores D-Bus CloseNotification; `omarchy-shell notifications dismiss <text>` closes every card whose summary *contains* the text, from any app. The body is StyledText (escape `& < >`) and must stay valid UTF-8 (cut by characters).
- **Hyprland config is Lua:** `o.bind(keys, desc, "cmd")` (/usr/share/omarchy/default/hypr/helpers.lua), `hyprctl dispatch 'hl.dsp.…'`, and `hyprctl configerrors` after `hyprctl reload`.
- **Adapters share the line protocol** documented above `adapter_claude`. Each must end with `exit <status>`: a turn with no result line is a failure. Every `tool` line carries an id and gets a `toolend` when its work is done; the comet, the radar and the moons run between the two.
- **Keep the vocabularies in sync:** the MOOD list in voice-prompt.md matches the `.mood` keys in reactions.json. Palette, pattern and motion names match orb.mjs (`palettes`, `patterns`, `motionSeconds`) and the pattern indices in orb.glsl. decide's mood options are the orb's (they drive the excited and surprised flourishes), not the agent's.
- **MOOD `clear` is one designed look** (mint, fine grain, breathe, chirp) in reactions.json. decide asks nothing for it, never carries its palette into the next turn, and keeps `mint` and `fine` out of its lists, so they can't be mixed into other moods. Add a new whole look the same way. Never blend decide's probabilities into in-between looks.
- **The orb's taste:** flat and minimal on a globe edge, with no lighting and no hard border. The eye is the pattern. Distortion stays near 1% of rim and 2 to 4% of stretch; more reads as cartoony. Sounds come only from the cue synth's six voices.
- **The rings pattern stays out of work:** decide's working choices and the `tool.*` reactions never use it, so a live mic looks distinct. Travelling rings are voice, in for the user and out for glitch. A returning moon's ping is the only ring during work.
- **Remote control** (`systemd/glitch-remote*`, `glitch _reap`): free sessions by restarting the whole server, never by killing one session's process. The app keeps showing a killed session connected while its turns hang.
- **Phone turns** (`GLITCH_PORTAL=phone`) write only to `$RT/phone/`, never the desk. libexec/portal's docstring is the wire format (every file, event, field and route); change it with the code. Desk and phone share `turn.lock`, the session and history, so a phone approval waiting its 5 minutes holds up desk requests too.
- **Phone fences:** a notification's Allow never approves by itself (action buttons work on a locked phone): it opens the app, which approves a `oneline` command only after unlock and shows anything longer first. A command the phone didn't fully receive (`cut` > 0) can't be allowed, by the server or by bin/glitch. Control and format characters are made visible in bash (`vis`), and the status phrase is made in bash (`status`), never parsed from labels in the page. Every file the page loads must be in `sw.js`'s `FILES`: the app is cached as a whole set and reloads only when idle. `web/demo.html` is a dev page.
- **Portal security:** `dispatch` in libexec/portal is the front door: everything outside `PUBLIC` needs a paired device cookie, Host is checked on every request and Origin on every POST. `devices` holds only each cookie's sha256. The cookie is `SameSite=Lax` because a home-screen launch doesn't send `Strict` cookies; the Origin check covers POSTs, and `/api/*` refuses navigations. A phone turn's approval is a file any same-user process could write, as the desk menu can be driven: a guardrail, not a wall (accepted). Root (pkexec) stays desk-only. The CA key must never exist after `glitch cert` (made on tmpfs, then shredded). Push endpoints are allow-listed (`PUSH_HOSTS`) and pushes carry no payload; the service worker asks `/api/notice` what to show.
- **Portal server:** one request per connection. Unpaired connections have a 10 s deadline and caps (8 per host, 16 in all, none for a host that has shown a paired cookie) so strangers can't hold all 32 slots; keep-alive would undo that. `KillMode=process` lets a running turn survive a portal restart. At launch the portal replays `events.jsonl` from the start to rebuild its state, so replay must stay side-effect free (`live` gates `.played` writes and pushes).
- **Never** `bypassPermissions` or Codex's `--dangerously-bypass-*` for glitch's turns, even for an agent `omarchy-agent` runs that way (grok): otherwise glitch runs agents with omarchy-agent's modes (glitch-remote's `bypassPermissions` is the user's choice; leave it). Tap-toggle, not hold, because releases of modifier-chord keys get lost.

Debug: `tail -f $XDG_RUNTIME_DIR/glitch/glitch.log`, `omarchy-shell -q glitch set '{"state":"thinking","reaction":{…}}'`, `omarchy-shell glitch event "tool x run"` (injects a live signal and prints `ok`; first `set` a `thinking` or `tool` state, or nothing shows), `libexec/preview`, `journalctl --user -u glitch-mind -u glitch-remote -u glitch-portal`, `quickshell log -p $OMARCHY_PATH/shell`.
