# glitch: agent notes

**This checkout is live.** install.sh symlinks it into place, so the next Super+D runs whatever is on disk. glitch's own agent runs in `WORKDIR` (~/Work) and can edit this repo mid-turn.

- **Replace bin/glitch atomically** (temp file, then `mv`): bash reads scripts lazily, and a running `_turn`/`_live` keeps reading the old inode.
- **Test turns in a scratch runtime:** `XDG_RUNTIME_DIR=$(mktemp -d) setsid glitch _turn "…" true` (`GLITCH_AGENT=codex` to pick the agent). The live runtime holds the user's session id, history and turn queue, so a test there resumes or cancels their real conversation. A worktree's `bin/glitch` uses the live runtime too, unless `XDG_*` point elsewhere. A stand-in `claude`/`codex` early in PATH exercises the error and needs-you paths; one that reports a context window still overwrites the real `~/.local/share/glitch/ctx.window`, which the scratch runtime does not cover.
- **Test the portal only with scratch `XDG_RUNTIME_DIR`, `XDG_DATA_HOME` and `XDG_CONFIG_HOME`,** as `GLITCH_PORTAL_PLAIN=1 bin/glitch portal` (plain HTTP on 127.0.0.1). A test pairing in the real data dir works on the live portal. Scratch data has no voice, so `glitch pair` refuses; write the `pair` or `devices` file directly (formats in libexec/portal's docstring).
- **plugin/ is a keepLoaded panel:** QML edits need `omarchy restart shell`. It refuses while the screen is locked, because the lock screen is the shell's: don't kill quickshell to get around it.
- **One orb, two hosts:** behaviour lives in `plugin/orb.mjs`, the look in `plugin/orb.glsl`. `Glitch.qml` (desk) and `web/orb.js` (phone) only feed inputs and draw; never put orb behaviour in a host. The shader hash stays integer-based, because sin-based hashes differ per GPU. After editing orb.glsl, run `plugin/build-shader` and commit `plugin/glitch.frag.qsb` (the fallback when qt6-shadertools is missing). Without root, unpack `qt6-shadertools` under `~/.local/share/glitch/qsb`, where build-shader also looks.
- **The orb has two inputs:** the state and reaction over IPC, and live signals that `ev` appends to `$XDG_RUNTIME_DIR/glitch/orb.events` (listed at the top of orb.mjs). Anything fast or factual is a signal, never a decision-model question. Only the script knows when work starts and ends (`turn`, `rest`). A host must not infer it from the state, which also changes for an approval or a recording mid-turn.
- **Seeing the orb while the screen is locked or asleep:** screenshots hang or show the lock. Stub the Quickshell imports in a copy of Glitch.qml next to orb.mjs, run it with `QT_QPA_PLATFORM=xcb DISPLAY=:0 /usr/lib/qt6/bin/qml`, and save frames with `grabToImage`. `GLITCH_RT` points it at a scratch orb.events.
- **Omarchy notifications:** only `-u critical` stays on screen, and `-r <id>` updates a card in place. The shell ignores D-Bus CloseNotification; `omarchy-shell notifications dismiss <text>` closes every card whose summary *contains* the text, from any app. The body is StyledText (escape `& < >`) and must stay valid UTF-8 (cut by characters).
- **A reply card can outlive its timer.** The shell never times out a critical card and restores it after a restart, while a reboot or logout empties `$RT`. A shell that has just started answers `dismiss` with "none" until it has restored its cards. So `card_sweep` (every run) closes it from `~/.local/state/glitch/card`, which goes only once the shell answers `ok`, or `none` after its first 30 s. A scratch runtime keeps its record in `$RT`.
- **Hyprland config is Lua:** `o.bind(keys, desc, "cmd")` (/usr/share/omarchy/default/hypr/helpers.lua), `hyprctl dispatch 'hl.dsp.…'`, and `hyprctl configerrors` after `hyprctl reload`.
- **Adapters share the line protocol** documented above `adapter_claude`. Each must end with `exit <status>`: a turn with no result line is a failure. Every `tool` line carries an id and gets a `toolend` when its work is done; the comet, the radar and the moons run between the two.
- **Keep the vocabularies in sync:** the MOOD list in voice-prompt.md matches the `.mood` keys in reactions.json. Palette, pattern and motion names match orb.mjs (`palettes`, `patterns`, `motionSeconds`) and the pattern indices in orb.glsl. decide's mood options are the orb's (they drive the excited and surprised flourishes), not the agent's.
- **MOOD `clear` is one designed look** (mint, fine grain, breathe, chirp) in reactions.json. decide asks nothing for it, never carries its palette into the next turn, and keeps `mint` and `fine` out of its lists, so they can't be mixed into other moods. `mint` is also the live mic's (`listening`); `fine` is clear's alone. Add a new whole look the same way. Never blend decide's probabilities into in-between looks.
- **The orb's taste:** flat and minimal on a globe edge, with no lighting and no hard border. The eye is the pattern. Distortion stays near 1% of rim and 2 to 4% of stretch; more reads as cartoony. Sounds come only from the cue synth's six voices.
- **The rings pattern stays out of work:** decide's working choices and the `tool.*` reactions never use it. The live mic is told apart by `mint`: decide can't pick it, and no `tool.*` or working-state reaction may use it. Travelling rings are voice, in for the user and out for glitch. A returning moon's ping is the only ring during work.
- **Remote control** (`systemd/glitch-remote*`, `glitch _reap`): free sessions by restarting the whole server, never by killing one session's process. The app keeps showing a killed session connected while its turns hang.
- **Phone turns** (`GLITCH_PORTAL=phone`) write only under `$RT/phone/` (a desk turn's one write there is the `fresh` event), and `turn.portal` alone says which portal owns the running turn. Desk and phone share `turn.lock`, the session and history: write shared runtime files only under the lock. A phone approval waiting its 5 minutes holds up desk turns too. libexec/portal's docstring is the wire format; change it with the code.
- **The phone allows only what it has shown in full.** Its approval `label` is the whole tool input for every tool (`APPROVE_JQ`). `oneline` is only a short, plain shell command that a collapsed notification shows whole. Never widen either. A notification's Allow never approves directly, because action buttons work on a locked phone: it hands off to the app, which approves only a `oneline` command, after unlock, and shows anything else first. Neither the server nor bin/glitch allows anything with `cut` > 0. bash, not the page, makes invisible characters visible (`vis`) and builds the status phrase (`status`); the page never parses labels.
- **Every file the page loads must be in `sw.js`'s `FILES`:** the page runs from one cached set and reloads onto a new one only when idle. `web/demo.html` is a dev page.
- **English is the reply; Mandarin is the work.** Mid-turn, only an approval's question and an aside (`glitch say`, the pairing code) are English. The mutter has its own pid file, because `hush` reads `speak.pid` as "glitch is talking" and a mutter there would turn a tap into "quiet" mid-turn. The mutter plays only while `working` holds: `stop_mutter` can miss one that is just starting, so `mutter_once` asks `working` again before it plays. `_mutter` is not setsid, so cancel's `pkill -s` reaches it. The mutter's line has no Latin letters, which Piper's Chinese voices speak as stray syllables. The phone's pinyin is what the voice read, recorded through Piper's private `_chinese_phonemizer` (re-check on a Piper bump), never another library's guess.
- **The trace is the phone's only.** The agent writes it, so the page hides it while an approval is up. A thought the mutter takes reaches the page from `cmd_mutter` as a `zh` trace, so its English can wait for the voice. Claude's thoughts arrive only with `--thinking-display summarized`, which `claude --help` doesn't list.
- **Testing the mutter** needs `think` lines (a stand-in `claude` must emit `thinking` blocks), `$RT/turn.pid`, a `thinking` or `tool` state, and on a phone turn a live pid in `$RT/phone/online`. Link the real `venv`, `voices` and `mind.key` into a scratch `XDG_DATA_HOME`. A scratch `XDG_RUNTIME_DIR` has no PipeWire socket, so set `PIPEWIRE_RUNTIME_DIR=/run/user/$UID` to hear the desk.
- **Phone subtitles follow the voice:** the page never shows reply text before it is spoken, unless no voice will play.
- **Portal security:** `dispatch` in libexec/portal is the one default-deny front door. Outside `PUBLIC` it needs a paired device cookie, and it checks Host on every request and the exact Origin on every POST. `devices` holds only cookie hashes. The cookie is `SameSite=Lax` because a home-screen launch doesn't send `Strict` cookies. Any same-user process can write an approval's answer file, as it can drive the desk menu: a guardrail, not a wall (accepted). Root (pkexec) stays desk-only. The CA key must never exist after `glitch cert`. Push endpoints are allow-listed (`PUSH_HOSTS`), and pushes carry no payload.
- **Portal server:** one request per connection. Unpaired connections get a 10 s deadline and per-host and total caps, so slow strangers can't hold every slot; keep-alive would undo that. `KillMode=process` lets a running turn survive a portal restart. The portal rebuilds its state by replaying `events.jsonl` at launch, so replay must stay side-effect free (`live` gates `.played` writes and pushes).
- **Never** `bypassPermissions` or Codex's `--dangerously-bypass-*` for glitch's turns, even for an agent `omarchy-agent` runs that way (grok): otherwise glitch runs agents with omarchy-agent's modes (glitch-remote's `bypassPermissions` is the user's choice; leave it). Tap-toggle, not hold, because releases of modifier-chord keys get lost.

Debug: `tail -f $XDG_RUNTIME_DIR/glitch/glitch.log`, `omarchy-shell -q glitch set '{"state":"thinking","reaction":{…}}'`, `omarchy-shell glitch event "tool x run"` (injects a live signal and prints `ok`; first `set` a `thinking` or `tool` state, or nothing shows), `libexec/preview`, `journalctl --user -u glitch-mind -u glitch-remote -u glitch-portal`, `quickshell log -p $OMARCHY_PATH/shell`.
